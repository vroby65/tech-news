Recap tech — 6 ottobre 2026

Nelle ultime 24 ore non emerge una nuova major release ufficiale di Anthropic, Google DeepMind o DeepSeek. Le novità più forti arrivano invece da OpenAI, che avvia il watermark testuale nell'UE, da GitHub con un nuovo benchmark aperto per la code review agentica, e dal mondo Linux/open source con ROCm 10.1, una grossa revisione di ZRAM, mold 3.0 riscritto in Rust e TrueNAS 27 RC.1. 1. OpenAI introduce textGrain: watermark invisibile nei testi ChatGPT e Codex nell'UE

OpenAI ha annunciato textGrain, un sistema di watermark testuale che modifica in modo statistico le scelte dei token senza inserire caratteri nascosti o marcatori visibili. Il rollout partirà nelle prossime settimane per gli output idonei di ChatGPT e Codex nell'Unione Europea; per i clienti API, invece, il watermark è già attivabile volontariamente a livello globale su modelli selezionati.

OpenAI sottolinea però limiti importanti: su testi brevi, contenuti molto vincolati e testo molto rielaborato la rilevazione peggiora. Nei test dichiarati dall'azienda, a un falso positivo target dell'1%, il rilevamento arriva a circa l'80% su passaggi da 200 token e circa il 95% su 400 token in domini favorevoli; sostituire il 10% delle parole con sinonimi fa scendere la rilevazione da circa 92% a 66%.

Perché conta: per chi usa ChatGPT e Codex in Italia è una modifica concreta al modo in cui il testo viene generato. Non identifica l'utente, non dimostra chi sia l'autore e non certifica che il contenuto sia vero. Da approfondire: sì, soprattutto perché OpenAI dichiara di voler rendere textGrain open source.

Fonte primaria: OpenAI

2. GitHub pubblica ReviewBench: benchmark aperto per gli agenti di code review

GitHub ha pubblicato ReviewBench, un benchmark aperto per valutare agenti di code review su pull request reali. Il corpus contiene 219 PR provenienti da 187 repository open source e copre 19 linguaggi; la distribuzione è stata modellata analizzando oltre 103 milioni di pull request GitHub.

Il ground truth combina review umane, modelli frontier e analisi statica. Sono disponibili dataset, rubriche di valutazione, runner self-service e leaderboard; è possibile portare il proprio agente, eseguirlo sul benchmark e confrontarlo con gli altri.

Perché conta: finora era facile dire che un reviewer AI “sembra bravo”, molto più difficile misurarlo in modo riproducibile. Da provare: sì, soprattutto per confrontare Copilot, Codex, Claude Code o agenti propri sullo stesso set di PR.

Fonte primaria: GitHub

3. AMD ROCm 10.1: più supporto AI, profiling e I/O per GPU AMD

ROCm 10.1 è disponibile. La release si concentra su inferenza AI, strumenti per sviluppatori e profiling: aggiunge supporto per Radeon AI PRO R9600, amplia virtualizzazione e sistemi operativi supportati, porta nuove versioni dei framework AI e aggiorna lo stack compiler a LLVM 24.

Tra le novità tecniche ci sono un fast path asincrono per hipFILE/Infinity Storage, API batch I/O, allocazioni host NUMA-aware in HIP e supporto WSL2 negli artifact TheRock in anteprima tecnica.

Perché conta: AMD continua a chiudere il divario software con CUDA, soprattutto su inferenza locale e toolchain. Da approfondire: sì per chi usa Radeon o Ryzen AI con llama.cpp, vLLM o SGLang; prima va sempre verificata la matrice ufficiale di compatibilità della propria GPU.

Fonte primaria: AMD ROCm · Sintesi: Phoronix

4. Linux ZRAM viene riorganizzato per consumare meno memoria e ridurre blocchi

Una nuova patch series riorganizza profondamente il backend di ZRAM. L'idea principale è separare gli stream di compressione e decompressione per CPU, evitando che un reader ad alta priorità resti bloccato dietro a un writer che detiene lo stesso stream lock.

La revisione elimina anche allocazioni inutili dei contesti secondari: gli sviluppatori indicano risparmi da decine a centinaia di KB per contesto e per core, che su molti core possono accumularsi. I test sintetici mostrano anche miglioramenti prestazionali notevoli, ma le patch sono ancora in review.

Perché conta: è particolarmente interessante sui sistemi con poca RAM e su macchine che usano zRAM intensamente. Da seguire: sì; potrebbe essere utile anche su piccoli ARM e Raspberry, ma non è ancora codice stabile upstream.

Fonte: Phoronix

5. mold 3.0: il linker ad alte prestazioni è ora riscritto in Rust

mold 3.0 è la prima major release dopo la riscrittura completa da C++ a Rust. Rimane pensato come sostituto drop-in di mold 2.42.1, ma il progetto punta ora a chiudere i gap di compatibilità con GNU ld, soprattutto nei linker script, con l'obiettivo dichiarato di poter diventare in futuro il linker di sistema predefinito su Linux.

La nuova versione richiede Rust 1.95 o successivo, usa Cargo al posto di CMake e non dipende più da oneTBB. La riscrittura dovrebbe inoltre rendere più sicura la gestione di input corrotti.

Perché conta: è una riscrittura significativa di un tool di sistema già usato in produzione, non un nuovo progetto sperimentale. Da provare: sì su build C/C++ o Rust dove il tempo di linking pesa realmente; eviterei però di sostituire subito /usr/bin/ld a livello di sistema.

Repository ufficiale · Dettagli release: Phoronix

6. TrueNAS 27 RC.1: OpenZFS 2.4, WebShare, TrueSearch e S3 nativo

È disponibile TrueNAS 27 RC.1, la release finora sviluppata con il nome TrueNAS 26. Usa Linux 6.18 LTS e OpenZFS 2.4 e aggiunge TrueSearch per la ricerca server-side, WebShare per accedere ai file dal browser, Fusion Pools 2.0 e supporto completo ai container LXC.

Arriva inoltre in early access la TrueNAS Object Interface, che espone accesso S3 nativo ai dataset ZFS. La stabile 27.0 è prevista per l'inizio di dicembre.

Perché conta: per self-hosting e NAS è una release molto sostanziosa, soprattutto grazie a WebShare, ricerca e object storage. Da provare: sì in laboratorio o VM; per un NAS con dati importanti aspetterei la stabile.

Fonte primaria: TrueNAS

7. GitHub Secret Scanning aggiunge chiavi Lovable, Pydantic AI e Supabase

GitHub Secret Scanning riconosce ora nuovi tipi di credenziali legati a Lovable, Pydantic e Supabase. Fra i nuovi detector ci sono lovable_api_key, logfire_token, pydantic_ai_gateway_api_key, supabase_oauth_access_token e supabase_scoped_personal_access_token.

Lovable entra anche nel partner program: se una sua chiave viene trovata in un repository pubblico, GitHub può segnalarla direttamente al provider affinché venga revocata o ruotata rapidamente.

Perché conta: i progetti AI moderni accumulano sempre più token e chiavi di servizi esterni, spesso usati da agenti e CI. Da fare: se usi uno di questi servizi, vale la pena controllare che Secret Scanning sia attivo e che nessuna credenziale sia finita nella cronologia Git.

Fonte primaria: GitHub
