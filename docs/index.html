Tech News Daily — 14 ottobre 2026

Novità del 13 ottobre e delle prime ore del 14: AI, Linux, software libero e sicurezza.

La notizia principale riguarda Linux Mint 27, che cambia radicalmente il calendario delle release. Interessanti anche Gemini 4 Argon, un nuovo strumento per risparmiare token con gli agenti e i progressi di un sistema operativo scritto in Rust.

1. Linux Mint 27 «Adrien»: release annuale prevista a Natale

Il Monthly News pubblicato il 13 ottobre conferma che Linux Mint 27 si chiamerà Adrien e sarà basato su Ubuntu 26.04. Rimangono confermate le edizioni Cinnamon, MATE e Xfce. La novità più importante è il passaggio a una release all'anno: dopo Mint 27 arriverà direttamente Mint 28, senza versioni intermedie. Il team presenta inoltre Clocks, una nuova applicazione per le sveglie del progetto Clockenstein, e conferma il lavoro sulla compatibilità Wayland. Perché conta: cambia il calendario degli aggiornamenti anche per chi utilizza MATE oppure Openbox. Natale è ancora una data indicativa e le funzionalità annunciate sono in sviluppo.

Fonte: Annuncio ufficiale Linux Mint

2. Gemini 4 Argon arriva in GitHub Copilot

Dal 13 ottobre GitHub Copilot supporta Gemini 4 Argon. Il modello è disponibile gradualmente per gli abbonamenti Pro+, Max, Business ed Enterprise, anche attraverso Copilot CLI e gli IDE supportati. GitHub dichiara miglioramenti significativi nei propri test di programmazione, soprattutto in CLI. Si tratta però di risultati del fornitore, non di benchmark indipendenti. Da approfondire: confronto con Codex e Claude Code, valutando sia la qualità delle modifiche sia il costo effettivo per attività completata.

Fonte: Changelog GitHub del 13 ottobre

3. Anthropic costruisce Scion, un controllo versione per agenti AI

Il 13 ottobre Anthropic ha raccontato come ha sostituito internamente Git con Scion, un sistema di controllo versione progettato per grandi quantità di operazioni automatizzate. L'azienda dichiara di essere passata da circa 2.500 a oltre 30.000 modifiche integrate quotidianamente fra maggio e settembre 2026. Scion utilizza un'architettura centralizzata, con client leggeri e operazioni di commit e merge gestite dal server. Perché conta: quando gli agenti scrivono moltissimo codice, il problema diventa gestire, verificare e integrare le modifiche. Non è un programma open source disponibile per sostituire Git nei propri progetti, ma è un caso tecnico interessante.

Fonte: Redesigning source control at Anthropic

4. ColGrep-Agent-2B: ricerca locale nel codice con meno token

LightOn ha presentato un agente aperto da 2 miliardi di parametri, disponibile anche in formato GGUF. Il modello cerca informazioni nei repository, segue i riferimenti e restituisce all'agente principale file e righe pertinenti. Nei test pubblicati dagli sviluppatori, utilizzandolo con Claude Code, il consumo di token API è diminuito del 34% e il costo stimato del 40%. Da provare: particolarmente interessante per chi usa Codex o Claude Code e vuole ridurre il consumo di token. Occorre verificare anche RAM, latenza e accuratezza sui propri repository.

Fontei: Analisi tecnica LightOn · Modello GGUF

5. OpenCode 2.0 presentato su Product Hunt

Il 13 ottobre è stato presentato OpenCode 2.0. È un agente di programmazione open source, indipendente dal modello utilizzato, disponibile come TUI, applicazione desktop e interfaccia web. Supporta provider commerciali e modelli locali. Perché conta: permette di sperimentare differenti LLM mantenendo un ambiente di sviluppo comune. Da provare: su Linux, confrontandolo con Codex e Claude Code. La presentazione non offre ancora benchmark indipendenti della nuova versione.

Fonte: Repository OpenCode

6. ONLYOFFICE Desktop Editors 10.0 integra AI locale

La release del 13 ottobre introduce AI Chat per documenti, fogli elettronici, presentazioni e PDF. Si possono utilizzare diversi provider, fra cui DeepSeek, oppure modelli locali attraverso Ollama, LM Studio e GPT4All. Arrivano inoltre una schermata iniziale rinnovata e il collegamento a Odoo. Attenzione: il modulo AI è ancora in beta e nelle edizioni open source deve essere installato separatamente. Da provare: su Linux, soprattutto per lavorare con documenti e PDF utilizzando modelli locali.

Fonte: Annuncio ufficiale ONLYOFFICE 10.0

7. Firefox Enterprise: gestione del browser sul proprio server

Mozilla ha presentato Firefox Enterprise, destinato a organizzazioni, scuole e pubbliche amministrazioni. La novità è una console amministrativa che può essere ospitata sull'infrastruttura dell'organizzazione. Permette di gestire centralmente policy, accessi, flussi di dati e utilizzo degli strumenti AI. Perché conta: maggiore autonomia nella gestione del browser e minore dipendenza da infrastrutture esterne. Non è un aggiornamento che occorra attivare nel Firefox personale.

Fonte: Annuncio Mozilla

8. Asterinas 0.19: X.Org su un sistema operativo scritto in Rust

Il 13 ottobre è stata pubblicata la versione 0.19 di Asterinas, un sistema operativo che punta alla compatibilità con Linux utilizzando prevalentemente Rust sicuro. Le principali novità sono un primo sottosistema DRM, il funzionamento di X.Org con OpenGL software tramite Mesa, il supporto iniziale AArch64 e miglioramenti per i container. Il progetto ora riesce anche a compilare se stesso. Include inoltre una skill per la revisione del codice tramite agenti AI. Da approfondire: sì, soprattutto per l'architettura del kernel. È ancora un sistema sperimentale, da provare in macchina virtuale.

Fonte: Annuncio Asterinas 0.19

9. GitHub protegge dai push accidentali di chiavi Anthropic

Dal 13 ottobre GitHub Secret Scanning riconosce nuove tipologie di chiavi API Anthropic. Nei repository con protezione attiva, comprese le repository pubbliche gratuite, il push contenente queste credenziali viene bloccato per impostazione predefinita. Sono stati aggiunti anche rilevamenti per Salesforce e Cloudsmith. Perché conta: è una protezione concreta per chi sviluppa agenti e utilizza API a pagamento. Rimane comunque necessario conservare le credenziali fuori dal codice e revocare immediatamente quelle eventualmente esposte.

Fonte: Changelog sicurezza GitHub

10. Kernel Linux: discussione sul tag «Assisted-by» per le patch AI

Una proposta discussa il 13 ottobre vuole eliminare l'obbligo di segnalare l'utilizzo di LLM nella preparazione delle patch attraverso il tag Assisted-by. Le opinioni dei manutentori sono divise: alcuni ritengono utile dichiarare l'assistenza AI, altri considerano poco significativo il tag. Perché conta: la diffusione degli agenti sta modificando anche le regole di collaborazione nei grandi progetti open source. La modifica è ancora una proposta, non una decisione definitiva.

Fonte: Phoronix, 13 ottobre
